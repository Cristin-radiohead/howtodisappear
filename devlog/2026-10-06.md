#COZE智能体API接入PythonCLI
📌 项目目标
将之前在Coze上搭建的智能体通过 API 接入自己的 Python 命令行应用，实现终端对话。
最终跑通「搭建智能体 → 获取凭证 → Python 调用 → CLI 对话」完整链路。

🧰 环境与工具

· 平台：coze.cn
· 语言：Python 3.14.6
· IDE：PyCharm 2026.2
· 依赖：requests、python-dotenv
· 系统：Windows 11

🗺️ 整体流程


1. 获取个人访问令牌（PAT）和 Bot ID
2. 在 PyCharm 中创建项目，配置 .env
3. 编写 Python CLI 调用 Coze API
4. 解决令牌、JSON、SSE 解析、非流式轮询等问题
6. 成功在终端与智能体对话

🔧 详细过程与问题解决



1· 登录 coze.cn，查看已创建的智能体，从智能体页面 URL 末尾提取 Bot ID（一串数字）。

2. 获取个人访问令牌（PAT）

· 进入 API & SDK → 授权 → 个人访问令牌 → 添加。
· 勾选 chat 相关权限（后续还需要 getChat、listChatMessages）。
· 令牌仅展示一次，格式如 pat_xxxxxxxx，立即保存。

3. PyCharm 项目配置

· 新建纯 Python 项目，安装依赖：
  ```bash
  pip install requests python-dotenv
  ```
· 在项目根目录创建 .env 文件：
  ```
  COZE_API_TOKEN=pat_你的令牌
  COZE_BOT_ID=你的bot_id
  ```
· 注意：等号两边无空格，值不加引号，文件编码必须为 UTF-8（无 BOM）。

4. 编写 CLI 代码（初版：流式）

```python
import os, json, requests
from dotenv import load_dotenv
from pathlib import Path

env_path = Path(__file__).parent / ".env"
load_dotenv(dotenv_path=env_path)

COZE_API_TOKEN = os.getenv("COZE_API_TOKEN")
COZE_BOT_ID = os.getenv("COZE_BOT_ID")

API_URL = "https://api.coze.cn/v3/chat"
HEADERS = {
    "Authorization": f"Bearer {COZE_API_TOKEN}",
    "Content-Type": "application/json"
}
```

5. 踩坑记录

报错 原因 解决方案
the token you entered is incorrect .env 未正确加载 / 令牌无效 用 Path(__file__).parent / ".env" 绝对路径加载；确认令牌以 pat_ 开头且勾选 chat 权限
the field http body provided is not a valid json 请求体格式错误 使用 json=payload 而非 data=json.dumps(payload)；确保字段名正确
ValueError: 请检查 .env 文件... .env 文件不存在 在 PyCharm 项目根目录重新创建 .env，确认文件名不是 .env.txt
变量读到 None 文件存在但内容未解析 检查 BOM 编码、key 拼写、等号空格；用 repr() 打印原始内容排查
'str' object has no attribute 'get' SSE 流中 data 不是字典 加 isinstance(data, dict) 判断
流式只返回 [done] 事件名在 event: 行而非 JSON 内 需解析 event: 行；或改用非流式轮询
非流式只返回 in_progress Coze 非流式接口异步返回 需轮询 GET /v3/chat/retrieve，再调 GET /v3/chat/message/list 取回复

6. 最终方案：非流式 + 轮询

核心逻辑：

1. 发起对话：POST /v3/chat，stream=False，拿到 chat_id 和 conversation_id。
2. 轮询状态：每秒调用 GET /v3/chat/retrieve，直到 status == "completed"。
3. 获取消息：调用 GET /v3/chat/message/list，提取 role == "assistant" 且 type == "answer" 的 content。

关键代码片段：

```python
import time

def chat_stream(user_input, user_id="cli_user_001"):
    payload = {
        "bot_id": COZE_BOT_ID,
        "user_id": user_id,
        "stream": False,
        "auto_save_history": True,
        "additional_messages": [
            {"role": "user", "content": user_input, "content_type": "text"}
        ]
    }
    response = requests.post(API_URL, headers=HEADERS, json=payload)
    result = response.json()
    chat_id = result["data"]["id"]
    conversation_id = result["data"]["conversation_id"]

    # 轮询
    retrieve_url = "https://api.coze.cn/v3/chat/retrieve"
    params = {"conversation_id": conversation_id, "chat_id": chat_id}
    for i in range(30):
        time.sleep(1)
        r = requests.get(retrieve_url, headers=HEADERS, params=params)
        status = r.json().get("data", {}).get("status")
        if status == "completed":
            break
        elif status == "failed":
            return

    # 取消息
    list_url = "https://api.coze.cn/v3/chat/message/list"
    r = requests.get(list_url, headers=HEADERS, params=params)
    messages = r.json().get("data", [])
    for msg in messages:
        if msg.get("role") == "assistant" and msg.get("type") == "answer":
            print(f"\nAI: {msg.get('content', '')}")
            return
```

📝 经验总结

· 令牌与 Bot ID 必须匹配同一工作空间，且智能体要发布为 API。
· .env 文件是新手最大的坑：路径、文件名、BOM 编码、等号空格都会导致读取失败。
· Coze 的流式接口事件格式特殊：事件名在 event: 行，数据在 data: 行，不能只在 JSON 里找 event 字段。
· 非流式接口是异步的：必须轮询 retrieve 再取 message/list，不能指望一次请求返回完整回复。
· 权限要勾全：除了 chat，轮询和消息列表还需要 getChat、listChatMessages。
