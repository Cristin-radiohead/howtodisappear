
# 项目日志

## 2026-10-11-12

### 目标
在昇腾 Atlas 200I DK A2 上跑通 YOLO11 推理，并做成 Web 展示工具。

### 完成事项

1. **PC 端导出 ONNX**
   - 关键参数：`opset=12, simplify=False, dynamic=False`
   - `simplify=True` 会破坏模型结构，导致输出异常

2. **开发板 ATC 转 OM**
   - 使用开发板自带的 CANN 7.0.RC1
   - 限制并行编译：`TE_PARALLEL_COMPILER=1`
   - 生成 `yolo11n.om`

3. **推理脚本**
   - `infer_yolo.py`：单张图片推理（CLI）
   - 关键：letterbox 预处理 + 直接使用模型输出（不做 sigmoid）+ NMS + 坐标还原

4. **Web 工具**
   - `image_detect.py`：图片上传检测
   - `camera_web.py`：摄像头实时 MJPEG 流
   - 用 Python 标准库 `http.server`，无需第三方依赖

### 关键发现

**YOLO11 的 OM 输出已经是概率值，不需要 sigmoid。**

原始输出 `类别维 max = 0.9395`，直接取用即可。加 sigmoid 后所有分数挤到 0.5，argmax 随机。

### 性能

- NPU 推理：10.28 ms
- 吞吐：97 FPS

### 项目卡住的地方
该项目卡住的次数最多、时间最长
1. CANN 版本不匹配
   · 开发板自带 CANN 7.0.RC1，由于昇腾社区找不到对应版本，PC 上装的是 7.0.0/7.0.1，后来为了下载配套算子包，升到 8.5.0。
   · 用 8.5.0 转出的 OM 在开发板上推理输出异常（全 0.5 或 nan），排查了很久才确认是版本不兼容。
   · 最后改用开发板原生 CANN 7.0.RC1 直接 ATC 转换才解决。
2. ATC 转换被 Killed
   · 开发板内存不足，ATC 进程被系统强制终止，报 Killed、EOFError、BrokenPipeError。
   · 尝试了加大 Swap、限制并行编译、后台运行，最终在开发板上转换成功。
3. 缺少 310b 专用算子包
   · 报 Conv2D is not found in op store，原因是只装了 Toolkit 没装 Ascend-cann-310b-ops。
   · 安装算子包后才通过。
4. ONNX 导出参数错误（最核心的卡点）
   · OM 转出来后，检测结果全是 cat，置信度全在 0.5 左右。
   · 一度以为是 CANN 版本问题，后来在 PC 上用 ONNX Runtime 做对比测试，发现 ONNX 输出最大分数只有 0.07，而 Ultralytics 直接推理是 0.42。
   · 最终定位到 simplify=True 破坏了模型结构，改成 simplify=False, opset=12 后恢复正常。
5. 后处理多加 sigmoid
   · OM 输出已经是概率值（max 0.94），后处理里又做了一次 sigmoid，把所有分数挤到 0.5 附近，argmax 随机输出。
   · 最后删掉 sigmoid，直接用 pred[:, 4:] 才正确检测。
6. 摄像头实时检测满屏误检
   · 摄像头画面里全是 cat、train、microwave 等误检框。
   · 根因同样是 sigmoid 陷阱 + 预处理用了 resize 而不是 letterbox。
   · 改成与 infer_yolo.py 一致的 letterbox + 直接使用输出后，摄像头检测正常（cup、mouse 正确识别）。
7. 开发板 OpenCV 无 GUI 支持
   · cv2.imshow 报 The function is not implemented，因为 OpenCV 编译时 GUI: NONE。
   · 最后改用 Python 标准库 http.server 做 MJPEG 流，浏览器查看，绕开了 GUI 限制。
8. 多线程调用 NPU 会话导致 ctx is NULL
   · HTTP 服务多线程同时调用 session.infer()，报 rtMalloc failed, context pointer null。
   · 最后把推理放在主线程，HTTP 服务只负责发送最新帧，用锁保护共享帧才解决。
