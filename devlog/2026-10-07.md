一、今日完成事项

1. 明确整体技术路线

· 确定三步走路径：搭建智能体 → 获取 API → 接入应用

· 确认新手首选平台为扣子（Coze），因其可视化拖拽、无需写代码

2. 智能体搭建与提交（已完成）

· 完成注册与登录扣子平台（coze.cn）
· 完成智能体创建路径：创建智能体 → 配置人设与回复逻辑 → 编排技能 → 调试 → 提交发布
· 确认人设与回复逻辑面板位于智能体编辑页左侧
· 遇到新版界面无“回到旧版”按钮的问题，尝试通过直接访问 code.coze.cn/home 绕过

3. 关键概念澄清

· MCP（Model Context Protocol）：AI 世界的“USB-C 接口”，用于连接外部工具与数据源
· 确认 MCP 在当前目标链路中非必要，属可选扩展能力，新手应先跑通最小闭环
· 模型选择建议：新手默认用豆包系列（中文理解好、响应快），需强推理时再切 DeepSeek
· Temperature 参数：精确模式 0.2 / 平衡模式 0.8 / 创意模式 1.0

4. 工作流创建方案制定

· 输出完整工作流创建方案，涵盖：
  · 核心概念：DAG 结构、三层组件体系（触发器 / 处理节点 / 输出节点）
  · 分步实操：新建项目 → 创建空白工作流 → 梳理业务 → 添加配置节点 → 变量管理 → 测试调试 → 发布 API
  · 避坑指南：变量名写错、输出不稳定、节点超时、变量作用域混乱
  · 实战案例：智能内容摘要工作流
· 解决了 “node 开始 has not be connected” 报错：原因是开始节点未连接下游节点，需手动拖拽连线

5. 评测集（测试集）创建方案制定

· 明确评测集在扣子罗盘（loop.coze.cn）中创建
· 前置条件：工作流必须已发布、账号有额度、仅限资源库工作流
· 分步流程：进入罗盘 → 新建评测集 → 配置数据列（选“Coze 工作流”） → 添加数据 → 提交版本
· 核心列配置：
  · parameter（Object 类型，字段名必须与工作流开始节点变量名完全一致）
  · bot_id（含数据库/变量节点时需要）
  · reference_output（可选，预期输出）
· 澄清 “请输入 input”：即 parameter 下 input 字段需填入的具体测试值，类型须与开始节点一致
· 测试集设计原则：核心链路覆盖、难度分层、异常输入覆盖、BadCase 回归

6. API 访问入口确认（为后续接入做准备）

· 新版扣子编程：开发页面右侧“➕” → 部署 → 部署记录“更多” → 查看
· 旧版扣子开发平台：发布 → 选择 API → 发布后查看
· 访问令牌创建：个人头像 → 扣子 API → 授权 → 个人访问令牌
· ⚠️ 接入自有应用为后续工作，今日仅确认入口位置，未实际接入

二、遇到的问题与解决

问题 原因 解决方案
找不到“人设与回复逻辑” 进入新版扣子编程界面 尝试直接访问 code.coze.cn/home 进入旧版
无“回到旧版”按钮 新注册账号或平台改版 通过旧版网址绕过，或确认账号类型
提示“node 开始 has not be connected” 开始节点未连接下游节点 从开始节点输出端口拖拽连线到下游节点输入端口
评测集 input 不知填什么 不理解字段含义 填入与工作流开始节点类型一致的测试值
