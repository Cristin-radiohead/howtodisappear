二、整体架构（最终方案）

```
Python CLI  →  One-API（标准 OpenAI 接口）  →  Coze 智能体 API
```

核心：把 Coze 智能体通过 One-API 包装成标准 model provider，让应用像调用 OpenAI 一样调用它。

三、修改过程记录

阶段一：搭建智能体并直连 API（初始方案）

做了什么：

1. 在 Coze 创建智能体，配置基础对话能力。
2. 发布时勾选「API」，获取 Bot ID 和 PAT 令牌。
3. 编写 app.py，用 requests 直接调用 Coze 原生 API：

```python
API_URL = "https://api.coze.cn/v3/chat"
HEADERS = {
    "Authorization": f"Bearer {COZE_API_TOKEN}",
    "Content-Type": "application/json"
}
```

4. 经过轮询 retrieve + message/list，CLI 成功对话。

问题：
这个方案虽然跑通了 CLI，但并没有把智能体作为 model provider。
Coze 智能体是 Agent Provider，接口是 Coze 原生格式，不是标准的 OpenAI 接口。任务要求“将上述作为 model provider”，直连方式不满足。

---

阶段二：明确差距，决定引入 One-API

分析：

对比项 直连 Coze（Agent API） 任务要求（Model Provider）
接口格式 Coze 原生 标准 OpenAI 格式
调用方式 异步轮询 同步返回
认证 Coze PAT 标准 API Key

结论：
需要一层转换，把 Coze 的 Agent API 包装成 OpenAI 兼容接口。选择 One-API 作为转换网关。

---

阶段三：部署 One-API 并配置 Coze 渠道

1. 安装 Docker Desktop

· 管理员 PowerShell 执行 wsl --install
· 安装 Docker Desktop，勾选 Use WSL 2 instead of Hyper-V
· 验证：docker run hello-world

2. 部署 One-API

```bash
docker run --name one-api -d --restart always -p 3000:3000 -e TZ=Asia/Shanghai -v one-api-data:/data justsong/one-api
```

访问 http://localhost:3000，默认 root / 123456。

3. 配置 Coze 渠道

字段 填写内容
模型类型 Coze
Base URL https://api.coze.cn
密钥 Coze PAT 令牌（pat_ 开头）
模型 bot-7693506287732211738（bot- + Bot ID）
UserID Coze URL 中提取的 UserID
分组 勾选 default

保存后点击「测试」，通过。

4. 创建 One-API 访问令牌

进入「令牌」→ 创建新令牌，勾选可访问模型 bot-7693506287732211738，保存并复制 sk- 令牌。

阶段四：修改应用接入方式（从直连改为 One-API）

1. 修改 .env

```env
ONEAPI_KEY=sk-你在OneAPI创建的令牌
COZE_BOT_ID=7693506287732211738
```

2. 新建 app2.py，改用 OpenAI SDK

```python
import os
from openai import OpenAI
from dotenv import load_dotenv
from pathlib import Path

env_path = Path(__file__).parent / ".env"
load_dotenv(dotenv_path=env_path)

COZE_BOT_ID = os.getenv("COZE_BOT_ID")

client = OpenAI(
    api_key=os.getenv("ONEAPI_KEY"),
    base_url="http://localhost:3000/v1"
)

def chat_stream(user_input, user_id="cli_user_001"):
    response = client.chat.completions.create(
        model=f"bot-{COZE_BOT_ID}",
        messages=[
            {"role": "system", "content": "You are a helpful assistant."},
            {"role": "user", "content": user_input}
        ],
        stream=False
    )
    print(response.choices[0].message.content)

def main():
    print(f"Coze CLI 已启动（Bot ID: {COZE_BOT_ID}），输入 exit 或 quit 退出。\n")
    while True:
        user_input = input("你: ").strip()
        if user_input.lower() in ("exit", "quit"):
            print("再见！")
            break
        if not user_input:
            continue
        print("AI: ", end="", flush=True)
        chat_stream(user_input)
        print()

if __name__ == "__main__":
    main()
```

阶段五：验证与踩坑

报错 原因 解决
failed to connect to the docker API at npipe Docker Desktop 未运行或 WSL 卡死 重启 Docker Desktop；wsl --shutdown 后重启
模型类型里没有 Coze One-API 版本过旧 docker pull justsong/one-api 升级
503 - 无可用渠道 模型名格式错误、分组未勾选 模型名改为 bot- + Bot ID；勾选 default 分组
token you entered is incorrect PAT 权限不足或 UserID 未填 重新生成 PAT 并勾选 chat 权限；填写正确 UserID
TypeError: 'NoneType' object is not subscriptable One-API 返回的 choices 为空 检查渠道配置；打印完整 response 排查

六、经验总结

· 直连 Agent API ≠ 作为 model provider：必须转换成标准 OpenAI 接口才算。
· One-API 的价值：把 Coze 的 Agent API 转换成标准 OpenAI 接口，实现“将智能体作为 model provider”。
· 必填项缺一不可：Base URL、PAT、UserID、bot- 前缀模型名、default 分组。
· Docker 和 One-API 必须保持运行，否则 CLI 会连接失败。
· 小程序门槛在资质，不在技术：个人主体几乎无法过审 AI 类目，企业主体需算法备案和类目审核。
