# 大模型的本地部署
日期：2026-10-05 状态：已完成 负责人：Cristin-radiohead
一、背景与目标
在本地用 Ollama 跑通 Qwen3-8B，用于日常问答与文档处理验证，要求数据不出本机，并可通过 OpenAI 兼容接口被其他应用调用。
二、环境准备
表格
下载为表格
导出为图片
项目	配置
系统	Windows 10/11、macOS 或 Linux
内存	8GB 起步，推荐 16GB 以上
存储	预留 20–50GB 可用空间
GPU	可选，NVIDIA 显卡配好 CUDA 驱动会明显更快
显存参考：8GB 显存跑 Qwen3-8B 属于比较合适的档位，日常写文案、总结、简单代码完全够用；4–6GB 显存建议优先选 4B 级别的轻量模型。
三、实施步骤
安装 Ollama：Windows 直接下载 exe 安装，Linux 用 curl -fsSL https://ollama.com/install.sh | sh。
确认服务正常：ollama list 查看已安装模型。
拉取并运行：ollama run qwen3:8b，首次运行会自动下载 Q4_K_M 量化模型（约 5.2GB）并启动。
验证 GPU 加速：观察任务管理器 GPU 3D 负载是否上升、显存占用是否在 4–6GB 区间。
后台服务模式（Linux）：nohup ollama serve > ollama.log 2>&1 &。
接口调用：服务默认监听 http://localhost:11434，接入 VSCode Continue、Codex 等 IDE 工具时 Base URL 填 http://localhost:11434/v1 即可，客户端会自动拼接 /chat/completions 路径。
四、遇到的问题与解决
长 prompt 后答非所问 / 多轮对话"假失忆"：Ollama 沿用 llama.cpp 的旋转上下文管理，默认 num_ctx 较小，超出后旧 token 会被逐出 KV cache。可在交互模式里手动 /set parameter num_ctx 40960，或按显存情况至少调到 8192。
num_ctx 设太大导致卡死：上下文越大 KV cache 占用越高。粗略参考 qwen3:8b：2048 约 1.2GB、8192 约 2.5GB、12288–16384 约 3.5–4.2GB，8GB 显存/核显设备建议取中间值。
模型加载失败：常见原因是显存不足（关闭其他占用显存的程序）、驱动不兼容（更新 NVIDIA 驱动）或依赖缺失（重启部署环境）。
生成质量不理想：补充更详细的提示词，temperature 建议 0.7–1.0，并明确指定输出格式。
清理空间：ollama rm qwen3:8b 可删除模型释放硬盘。
