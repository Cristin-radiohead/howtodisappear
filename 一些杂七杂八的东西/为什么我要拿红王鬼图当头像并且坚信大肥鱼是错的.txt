🎯 你实际解决的过程

第一步：怀疑 ONNX 本身

当开发板 OM 输出异常时，你没有继续在开发板上折腾，而是回到 PC 上用 ONNX Runtime 做对比测试：

· 同一张 bus.jpg，ONNX Runtime 输出最大分数只有 0.072
· 但 Ultralytics 直接推理同一模型，置信度 0.42

这一步是转折点：同一模型、同一图片，ONNX 输出比原模型低 6 倍 → 问题出在 ONNX 导出，不在 CANN 转换。

第二步：找到 ONNX 导出的元凶

你重新导出 ONNX，把参数改成了：

```python
model.export(format="onnx", opset=12, simplify=False, dynamic=False)
```

关键就是 simplify=False。之前用 simplify=True，简化工具破坏了模型结构，导致输出失真。

重导后再用 ONNX Runtime 验证 → 最大分数 0.39，和 Ultralytics 的 0.42 基本一致。ONNX 修好了。

第三步：在开发板上重新转 OM

用修好的 ONNX，在开发板上跑 ATC：

```bash
atc --model=/root/yolo11n.onnx \
    --framework=5 \
    --output=/root/yolo11n \
    --input_shape="images:1,3,640,640" \
    --soc_version=Ascend310B4 \
    --output_type=FP32 \
    --input_format=NCHW
```

这次成功，且没有加 --precision_mode=force_fp32（加了反而会出 nan）。

第四步：识破 sigmoid 陷阱

OM 转换成功后，你的 infer_yolo.py 里本来有段"sigmoid 判断"：

```python
if scores.max() < 1.0 and scores.min() >= 0:
    scores_sig = 1.0 / (1.0 + np.exp(-scores))
    if scores_sig.max() > 0.3:
        scores = scores_sig
```

但通过调试打印，你发现：

```
类别维: min=0.0000, max=0.9395, mean=0.000077
```

最大分数已经是 0.94，这就是概率值，不需要 sigmoid。

你最终确认：YOLO11 的 ONNX/OM 输出已经内置了 sigmoid，后处理必须直接用 pred[:, 4:]，不能再激活。

第五步：严格照搬已验证的 infer_yolo.py

Web 服务脚本 image_detect.py 一直出问题，最后你没有再自己改写后处理，而是把 infer_yolo.py 的逻辑原样搬过来：

· letterbox 预处理（不是 resize）
· 直接使用模型输出（不做 sigmoid）
· 坐标还原用 (x - dw) / ratio（不是 (x - pad) / scale）
· 阈值 0.45（和 infer_yolo 一致）

改完后一次成功。

🧠 你"死磕"成功的真正原因

我当时的判断 实际情况
CANN 版本不匹配 ❌ 不是主因，开发板原生 CANN 转换成功
YOLO11 不适配 CANN 7.0.RC1 ❌ 不是，OM 能正常加载和执行
建议换 YOLOv5 绕过 ❌ 换了就做不了现在的作品

真正的问题是：

1. ONNX 导出参数错误（simplify=True 破坏模型）
2. 后处理多加了 sigmoid（YOLO11 输出已是概率）

你成功的关键动作：

· 不被"版本不匹配"这个结论带走，坚持排查
· 用 ONNX Runtime 做最小复现，用数据定位问题在 ONNX 而非 CANN
· 回到已经被验证正确的 infer_yolo.py，不做任何"改进"
· 用调试打印看原始输出数值，而不是凭猜测加激活函数
