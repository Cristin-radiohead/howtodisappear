智能体线：扣子搭建 → OneAPI 封装 → API 接入 CLI / 小程序
· YOLO 线：训练 → 实时推理 → Web / Electron → 昇腾开发板部署

两条线的共同点：都走"先用最简单的方式跑通，再逐步逼近真实部署场景"的路线。

---

二、智能体线：从对话到应用

阶段 1：明确方向

一开始你没有直接写代码，而是先想清楚：智能体怎么变成我能用的东西？
答案是三步：搭建 → 作为 Model Provider → 通过 API 接入应用。

阶段 2：选平台

在扣子、Dify、n8n 之间，你选了扣子。原因：可视化、无需写代码、对新手最友好。

阶段 3：踩坑与澄清

过程中遇到一些新手常见困惑：

· 找不到"人设与回复逻辑"（新版界面问题）
· 不知道 MCP 是什么、要不要接（结论：非必需）
· 模型选哪个（豆包/DeepSeek）、Temperature 怎么调

这些都不是技术难点，而是对新平台不熟悉造成的认知成本。

阶段 4：接入方式的演进

你最初考虑 CLI → 小程序，后来发现小程序过审门槛高，于是用 OneAPI 做统一网关，把扣子智能体包装成 OpenAI 兼容接口。
这样 CLI、Web、小程序都能用同一套调用方式。

阶段 5：收尾

最后产出一个完整的智能体仓库，包含 README、项目日志、踩坑记录。

---

三、YOLO 线：从训练到边缘部署

这条线比智能体长得多，也更有技术含量。可以分成四个大阶段。

阶段 1：PC 上跑通基础流程

目标：先跑通"训练 → 推理"，建立信心。

· 用 COCO8 数据集训练 YOLO11n，拿到 best.pt
· 用 OpenCV 做摄像头实时推理
· 遇到摄像头锁、OpenCV 后端问题，用 cv2.CAP_DSHOW 解决

关键心态：这一步不追求精度，只追求流程跑通。

阶段 2：做成可展示的应用

目标：让检测结果能被看见、能演示。

· FastAPI 后端提供 /detect 接口
· HTML 前端调用摄像头、显示结果
· 再用 Electron 包装成桌面应用

这一步的坑主要是工程问题：Electron 窗口闪退、路径错误、变量未定义等，都是"写过一遍就懂"的东西。

阶段 3：转向真实边缘设备（核心）

目标：把 YOLO 部署到昇腾 Atlas 200I DK A2。

这一步是整个项目的分水岭，也是你花时间最多的地方。

思路演进：

1. 先搞清楚开发板有什么：CANN 7.0.RC1、Ascend310B4、无摄像头
2. 尝试用视频文件推理 → H.264 打不开 → 改用图片
3. 在 PC 上做 ATC 转换 → CANN 版本不匹配 → 转出来的 OM 输出异常
4. 在开发板上直接 ATC 转换 → 成功
5. 但 OM 推理输出还是全 0.5 / cat

关键转折点：

· 你用 ONNX Runtime 在 PC 上做最小对比测试
· 发现同一模型、同一图片，ONNX 输出 0.07，Ultralytics 输出 0.42
· 定位到 ONNX 导出参数错误：simplify=True 破坏了模型
· 改用 simplify=False, opset=12 重新导出 → ONNX 恢复正常

第二个关键转折点：

· 重新转 OM 后，检测结果仍然是 cat
· 通过调试打印发现：YOLO11 的 OM 输出已经是概率值（max 0.94）
· 而你之前多加了 sigmoid，把所有分数挤到 0.5 → argmax 随机
· 删掉 sigmoid，直接用 pred[:, 4:] → 检测正确

阶段 4：收尾成完整作品

· 把 infer_yolo.py 的验证逻辑原样搬进 image_detect.py 和 camera_web.py
· 做成图片上传 + 摄像头实时两种模式
· 用 Python 标准库 http.server 实现，不依赖第三方

---

四、两条线的共同方法论

把两条线抽象出来，你的做事方式其实很一致：

1. 先用最简单的方式跑通，再逐步逼近真实场景

· 智能体：先纯对话 → 再接 API
· YOLO：先 COCO8 → 再开发板；先图片 → 再摄像头

2. 遇到问题时先做"最小复现"

· 视频打不开 → 先测单张图片
· OM 输出异常 → 回 PC 上跑 ONNX 对比
· 检测全是 cat → 打印原始输出数值看五、你实际完成的东西

智能体线：

· 在扣子搭建智能体
· 用 OneAPI 封装成统一 Model Provider
· 接入 CLI、小程序（可选）

YOLO 线：

· YOLO11n 训练（COCO8）
· ONNX 导出（踩过 simplify 的坑）
· ATC 转 OM（踩过 CANN 版本、算子包、内存的坑）
· 开发板 NPU 推理（10.28ms / 97FPS）
· Web 图片上传检测
· 摄像头实时 MJPEG 检测

方法论收获：

· 跨平台部署的版本匹配原则
· 用最小复现定位问题
· 不被"看起来对"的结论带走
叙事建议

可以按"目标 → 试错 → 转折 → 突破 → 收尾"五段式讲：

1. 目标：在昇腾开发板上部署 YOLO，做成可展示的应用
2. 试错：视频打不开、CANN 版本不匹配、OM 输出全是 cat
3. 转折：用 ONNX Runtime 做对比测试，发现是 ONNX 导出参数问题
4. 突破：重新导出 ONNX、删掉多余的 sigmoid、检测正确
5. 收尾：做成图片上传 + 摄像头实时两种 Web 模式

核心亮点：不是"AI 帮我解决了问题"，而是"我在 AI 给出错误方向时，用实验数据自己找到了真因"。
