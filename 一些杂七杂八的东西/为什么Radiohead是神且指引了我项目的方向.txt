Slide 4：模型转换的坎坷

目标：把 PC 训练的 YOLO11n 转成开发板能用的 OM 模型。

我尝试的路线：

1. PC 上装 CANN 7.0.0 → 报错 Conv2D not found（缺 310b 算子包）
2. 升级到 CANN 8.5.0 + 310b-ops → ATC 转换成功
3. 但 OM 在开发板上推理输出异常（全 0.5 / nan）

关键发现：

开发板 CANN 7.0.RC1 vs PC CANN 8.5.0 版本不匹配。

解决：

· 直接在开发板上用自带 CANN 转 OM
· 加大 Swap、限制并行编译、后台运行

---

Slide 5：ONNX 导出的隐藏坑

问题：开发板转出来的 OM，检测结果仍然全是误检。

排查过程：

1. 在 PC 上用 ONNX Runtime 跑同一个 ONNX → 最大分数只有 0.07
2. 对比 Ultralytics 直接推理 → 置信度 0.42
3. 定位：ONNX 导出参数有问题

关键修复：

```python
model.export(format="onnx", opset=12, simplify=False, dynamic=False)
```

simplify=True 会破坏模型结构。

---

Slide 6：后处理的致命误区

问题：OM 输出做 sigmoid 后，所有分数都变成 0.50。

错误代码：

```python
if scores.max() < 1.0:
    scores = 1.0 / (1.0 + np.exp(-scores))  # ❌
```

为什么错：

YOLO11 的 OM 输出已经是概率值（max 0.94），再加 sigmoid 会把所有分数挤到 0.5 附近，argmax 随机输出 cat。

正确做法：

```python
class_scores = pred[:, 4:]   # 直接用
max_scores = np.max(class_scores, axis=1)
```

Slide 7：最终方案 —— 端到端链路

完整流程：

```
PC 训练 YOLO11n
    ↓
导出 ONNX (opset=12, simplify=False)
    ↓

    ↓
ais_bench NPU 推理
    ↓
letterbox 预处理 + 直接使用输出 + NMS + 坐标还原
    ↓
Python 标准库 HTTP 服务（MJPEG / 图片上传）
    ↓
PC 浏览器访问
```

性能：NPU 推理 10.28 ms/帧，约 97 FPS。
